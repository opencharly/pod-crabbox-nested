# 2026.309.0812 — feat(containerd-nested): import /etc/containerd/conf.d drop-ins

## Summary

The inner containerd ran on its built-in defaults. nerdctl-full's `containerd.service` has `ExecStart=/usr/local/bin/containerd` with no `--config`, the image carried no `/etc/containerd/config.toml`, and containerd's defaults have an empty `imports` list — so every `/etc/containerd/conf.d/*.toml` drop-in was inert, including the k3s CNI directory keys `opencharly/pod-crabbox-k3s` writes (opencharly/pod-crabbox-k3s#2).

This change writes the missing file in `candy/containerd-nested/charly.yml`:

```toml
version = 3
imports = ["/etc/containerd/conf.d/*.toml"]
```

`version = 3` is measured from the shipped artifact, not guessed: nerdctl-full 2.1.2 installs containerd v2.1.1, whose own `containerd config default` emits `version = 3`. The version is not cosmetic — a v4 config panics that binary. No unit `--config` flag is added: the config file is the one mechanism.

Two build-scope checks are added:

- `nested-containerd-config-version` — the written `version` equals the shipped binary's own `containerd config default` first line.
- `nested-containerd-imports` — a probe drop-in written into `/etc/containerd/conf.d/` appears in `containerd config dump` inside the built image; the probe is removed on exit.

The candy `description:` and the image `description:` are updated in the same change. Both emitted artifacts are verified at their boundary below (the generated Containerfile section and the built image's `ai.opencharly.description` label).
