# 2026.309.1522 — feat(bed): add the disposable R10 bed for the nested-engine lease

Adds `check-pod-crabbox-nested-engine`, the first disposable R10 bed for the nested-engine lease image, and fixes a real defect the bed exposed in the candy's own check surface.

## Summary

This image's whole point is the **inner containerd**, and that is precisely the claim no build-scope check can make: `charly check box` proves the binaries and the config exist; it never proves the daemon answers. This repo's `AGENTS.md` says so directly — *"a claim that needs a running inner engine belongs in a deploy-context bed, not here"* — which is why this bed is the right instrument and a stronger `check:` is not.

The bed is `disposable: true` and drives three steps:

| step | id | what it asserts |
|---|---|---|
| ABSENCE | `nested-engine-absent-before-perform` | the inner engine is **not serving**, and the lease refuses a freshly generated key |
| PERFORM | `nested-engine-performs-the-start` | the lease unit consumes the inputs and `containerd.service` starts the inner engine |
| PRESENCE | `nested-engine-present-and-lease-holds` | the inner containerd answers, the `conf.d` drop-in is effective **in the running daemon**, `/etc/machine-id` is **populated by this boot**, and the lease holds over SSH |

The absence step is the one that makes this a gate rather than an inspection: it asserts the engine is not yet serving, so a target that never started it cannot read as "nothing applied yet".

### The defect the bed found, fixed here rather than deleted

`candy/containerd-nested/charly.yml` carried:

```yaml
- check: /etc/machine-id exists and is empty
  id: nested-machine-id-empty
  command: test -f /etc/machine-id && test ! -s /etc/machine-id
```

That is true of the **image** and false of a **booted lease**, where systemd generates the id at first boot. It has no `context:`, so it ran in the deploy context too, and `check-live` FAILED on it (run `2026.309.1426`).

Scoping it to `context: [build]` was tried and rejected: it left `skipped_checks: 4`, i.e. it bought a green run by not looking.

The fix asserts the clone-identity contract **in both contexts**, which is what the contract actually says:

```yaml
- check: /etc/machine-id carries the clone-identity contract in this context
  id: nested-machine-id-clone-identity
  command: |
      set -eu
      if [ "$(ps -p 1 -o comm=)" = systemd ]; then
        test -s /etc/machine-id
        grep -Eq '^[0-9a-f]{32}$' /etc/machine-id
      else
        test -f /etc/machine-id
        test ! -s /etc/machine-id
      fi
```

The build half is the one that matters for cloning: an image that **baked** an id would pass the deploy half in every lease that shares it, which is exactly the sharing the contract forbids.

**`skipped_checks: 0` is the test**, not a zero in the `N steps:` line: build-time mutating `run:` steps legitimately SKIP in check-live as "verify-only mode (mutating step)" and that is not a failure. `skipped_checks` counts skipped `check:` steps, which is what must be zero.

The bed's own steps in `check-live`:

```console
  PASS  check absence — the inner engine is not serving and the lease refuses the freshly generated key  [nested-engine-absent-before-perform]  exit=0
  PASS  check perform — the lease unit consumes the inputs and containerd.service starts the inner engine  [nested-engine-performs-the-start]  exit=0
  PASS  check presence — the inner containerd answers, the drop-in is effective, the clone identity is this lease's own, and the lease holds over SSH  [nested-engine-present-and-lease-holds]  exit=0
```

**What is deliberately not claimed.** The containerd **lease substrate** is not claimable in this toolchain: a `pod:` deploy's authored `engine: containerd` is dropped by the check-bed `config`/`start` path (it emits a podman quadlet) and `charly deploy add --engine` is an unknown flag at `2026.307.1232` — `opencharly/charly#1109`. Neither selector is authored here. The Docker-compatible socket for the Actions runner is a host-side pass-through, not an image artifact (`opencharly/pod-crabbox-nested#1`) and is not claimed. This bed claims the image's engine-independent running contract, like its two sibling beds.
