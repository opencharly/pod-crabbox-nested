## Summary

Adds `pod-crabbox-nested`: the nested-engine lease image for the Crabbox `containerd` provider, one of the `pod-crabbox-<variant>` images tracked by opencharly/opencharly#869 (W5.2). It is the pinned `opencharly/pod-crabbox-systemd` lease contract plus an inner containerd, an inner krun, and nerdctl.

- **`charly.yml`** — the image: `base: ghcr.io/opencharly/pod-crabbox-systemd:2026.308.2335` (pinned OCI base), `user: root` with `entrypoint: [/sbin/init]` (the inherited systemd-as-PID-1 handoff), and `distro: [cachyos, arch]` + `build: [pac]` declared explicitly because an external OCI base does not inherit the CachyOS chain.

### Scope notes

- **Arch package names, not the row's Fedora spellings.** The `pod-crabbox-nested` row names `iptables-nft`, `iproute`, `bzip2-libs` and `crun-krun`. On Arch/CachyOS they are provided by `iptables` (which `Provides: iptables-nft`), `iproute2`, `bzip2` and `krun` respectively. `iptables`, `iproute2` and `bzip2` are already in the base image, so they are asserted by checks rather than re-declared.
- **`libbz2.so.1.0` is already the base image's.** Arch's `bzip2` package ships `/usr/lib/libbz2.so.1.0 -> libbz2.so.1.0.8`; the check asserts the soname resolves instead of replacing a package-owned file with an identical link.
- **The Docker-compatible socket is not shipped.** The row asks for "a docker-compatible socket for the Actions runner". The image is containerd + nerdctl, and the row's package list names no Docker-API daemon; the only docker socket the org documents is crabbox's local-container **host** socket pass-through (`--local-container-docker-socket`), which is a consumer action. A `/var/run/docker.sock` symlink to containerd's CRI socket would satisfy the path but not the protocol, so it was not added. Filed as #1 with the evidence and the three candidate resolutions.
